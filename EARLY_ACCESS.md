# Early access setup

The `/early-access` page requires a name and email address. On submission, the
server saves them to Supabase and only returns the installer URL after the save
succeeds. Signups with an email that already exists are accepted without
creating a duplicate row.

## Supabase setup

Create a Supabase project, then run this SQL in its SQL Editor:

```sql
create table public.early_access_signups (
  id bigint generated by default as identity primary key,
  name text not null,
  email text not null unique,
  created_at timestamptz not null default now()
);

alter table public.early_access_signups enable row level security;
```

The signup API uses the project service-role key server-side, which bypasses
row-level security. Do not expose this key in frontend code or use a `VITE_`
prefix. The table has no public read or write policies.

## Vercel environment variables

Set these variables in Vercel and redeploy:

- `SUPABASE_URL`: the project URL from Supabase project settings.
- `SUPABASE_SERVICE_ROLE_KEY`: the server-only service-role key from project
  settings.
- `INSTALLER_DOWNLOAD_URL`: an HTTPS URL to the latest Procedia installer ZIP.

The signup endpoint is `POST /api/early-access` and accepts JSON containing
`name` and `email`. It validates both fields, upserts by the unique email, and
returns the download URL only after Supabase confirms the request. Configure
rate limiting at the hosting edge before a public launch.

`npm run dev` starts only Vite and does not serve the API route. Use Vercel's
development runtime or a Vercel preview deployment to test signup and download
end to end.
